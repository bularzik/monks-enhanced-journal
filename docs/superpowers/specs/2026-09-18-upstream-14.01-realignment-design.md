# Upstream 14.01 realignment — design

Date: 2026-09-18. Status: draft for Dan's review.

## Context

Upstream released MEJ 14.01 on 2026-09-13 as one squashed commit (tag `14.01`, `9d66fb9`) without using PR #820 or #821. On 2026-09-18 both PRs were closed with summary comments and coffiarts was told how to rebase #797 (they own the DSA5 currency sites, the "Allow GM" setting, and the `onAcceptOffer` `currencyId(k)` fix). The per-commit comparison and the Discord-thread review live in `docs/superpowers/triage/2026-09-18-upstream-14.01-vs-pr821.md`: of 85 non-chore PR commits, 41 fixes are absent from 14.01, 20 are present as partial or broken alternatives, 21 are present; of 20 Discord threads, 14.01 resolves 11 and 8 remain open or partial. Four suspected 14.01 defects were confirmed live (duplicate-tab open crash, close-hook page lookup, ImagePopout `_render`, string-key `currencyId`), and the Detach control claim was disproved.

Dan approved (2026-09-18) four streams: close the PRs (done), live-verify (done), re-raise the missing fixes as small PRs on 14.01, and rebase the fork's integration line onto 14.01 with the adoptions 14.01 got right. This spec covers the two remaining streams.

Goals: (1) get each still-missing fix in front of the maintainer as a diff he can take or leave in one sitting; (2) make the fork's own line (`integration-14.08`, the companion's host) a superset of 14.01 so companion testing and future fixes start from current upstream code.

Non-goals: enhancement PRs (`enh/*`, dark theme) until the maintainer's dark-theme thread has been read; anything coffiarts owns; the encounter control icon (maintainer ruling: intentionally blank).

## Stream A — upstream single-issue PR series

### Shape

- Base: `upstream/main` at `9d66fb9` (the `14.01` tag). One branch per PR, named `up/<slug>`, pushed to `origin` (bularzik fork), PR opened against `ironmonk108:main`.
- One issue or one subsystem per PR. The diff is written against 14.01's code, not cherry-picked: the target functions have moved (his `_activatingTab` debounce, his `currencyId()` helper, his `_getHeaderControls` rewrite), so each port re-derives the change from the fix's intent and our original commit, then keeps only what 14.01 still lacks.
- No `CHANGELOG.md` or `module.json` edits (he squashes releases himself). `Co-authored-by` credits carry over on ports of other people's work.
- PR body template: symptom, cause (file:line in 14.01), fix, how verified (world/system, steps), links to the tracker issue and the Discord thread where one exists. Footer: the Claude Code attribution line.
- Comments on the tracker issues: none until the PR is merged (the maintainer works from Discord; the closed-PR comment already tells issue watchers what is coming).

## Execution order

1. Harness worktree + install symlink setup (shared by both streams).
2. Stream A batch 1: six PR branches in parallel worktrees, each verified twice, then opened.
3. Stream B: merge, rulings, adoptions, reverts, harness updates, suite, release, symlink restore.
4. Stream A batch 2 in priority order, two or three PRs at a time, each verified the same way.

Batch 1 goes before the merge because it is the outward-facing deliverable and needs nothing from the merge. The merge goes before batch 2 because batch 2's larger ports are easier to write once the same code has been reconciled against 14.01 in the fork.

## Risks

- The maintainer may ignore small PRs the way he ignored the large one. Mitigation: each PR is a few dozen lines with a live-verified repro he can run in a minute, and the Discord threads he left open get a reply linking the PR once it is up.
- The merge is the same size as the 2026-08-15 sync that needed four amendments. Mitigation: CRLF normalisation first, rulings written per hunk, harness suite as the gate, and the three big files reviewed hunk-by-hunk before the suite runs.
- Disk: 3.4 GB free on the machine; run suites with `--trace off` as before.
- The install symlink swap needs Dan's `!` commands if the classifier still blocks `rm`/`ln`.

## Out of scope

Enhancement branches (`enh/*`) as upstream PRs; a dark-theme PR (blocked on reading the maintainer's un-exported thread); the right-click-spam ContextMenu crash (not reproduced by 64 rapid right-clicks; needs a manual repro first); the Edit Item dialog overlap (needs-info since Aug 15).
