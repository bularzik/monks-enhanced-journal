## Flagged deliberate reverts

12 cases where the maintainer's 14.00 build contains a plausible independent fix attempt at the *same* bug our #820/#821 work already fixed, but a different (and in each case judged inferior, incomplete, or differently-scoped) implementation. Kept ours per `keep-ours-unless-additive`. Each entry below is written to stand alone for Dan's review — no cross-referencing required.

1. **`JournalEntryPage.prototype._onClickDocumentLink`** (`monks-enhanced-journal.js`) — Ours: a direct prototype override, fixed (`7aaebc5`) to use `this` instead of a stray undefined `page` reference. Theirs: the same logic wrapped via `patchFunc(..., "MIXED")` with a conditional fallback to core click handling when the click didn't originate inside `#MonksEnhancedJournal`. Theirs doesn't reintroduce the original bug (also correctly uses `this`), but changes MEJ's link-interception scope globally. Kept ours as the narrower, already-verified change.

2. **"Allow GM" gate** (`monks-enhanced-journal.js`, 5 hunks) — Ours: `MonksEnhancedJournal.isAllowedToUseEnhancedJournal()` (PR #797, fix `7cc2140`) checks `game.user.isGM && setting('allow-gm') || !game.user.isGM && setting('allow-player')`. Theirs: `static get canShowEnhancedJournal` checks `game.user.isGM || settings("allow-players")` — references a setting key (`allow-players`, plural) that is **never registered** (the real key is singular `allow-player`), so the theirs' check is permanently broken (always falsy for the setting half) *and* always allows GMs unconditionally, silently dropping the #797 "Allow GM" opt-out entirely. Kept ours; also removed the now-dead/buggy `canShowEnhancedJournal` getter definition.

3. **`canDropOnActorSheet(sheet)` drop-item guard** (`monks-enhanced-journal.js`, `apps/enhanced-journal.js`, `sheets/EnhancedJournalSheet.js`, `sheets/LootSheet.js`) — Ours: shared `MEJHelpers.canDropOnActorSheet(sheet)` (fix `b9ba286`) excludes cyphersystem, dnd4e, dcc, **and pf2e**. Theirs: an independently-authored `MonksEnhancedJournal.canDropOnActorSheet(sheet)` excludes only cyphersystem, dnd4e, dcc — missing the pf2e exclusion. Kept ours as the strictly more complete guard.

4. **Defunct-relationship display** (`sheets/EnhancedJournalSheet.js`) — Ours (fix `0fbb3c1`): dedups defunct entries, `continue`s immediately, sets richer fields (img, shoptype, role, defunct flag). Theirs: a simpler variant (`results.defunct`, no dedup, falls through as an `else if`). Kept ours as the more complete implementation of the same feature (base had none at all).

5. **Roll-table text-result handling** (`sheets/EnhancedJournalSheet.js`) — Ours (fix `65dd38a`, #800): an `isCurrencyText` check before treating text as currency, plus a fallback that creates a generic loot item rather than silently dropping plain-text results (e.g. "Rusty Sword"). Theirs: only adds an empty-text guard before treating all non-empty text as currency-formula text — still mis-parses/drops plain-text results, does not fix #800. Kept ours as the actual bug fix.

6. **Relationship delete-cascade key** (`sheets/EnhancedJournalSheet.js`) — Ours (fix `efca9e1`): a single `deleteItem(id, container, cascade=true)` using the corrected key `this.document.parent?.id ?? this.document.id`. Theirs: splits into `deleteItem`/`deleteRelationship`, independently computing the *same* corrected key. Functionally equivalent fix to the identical bug, structurally different. Kept ours (the existing, already-tested implementation) per the rule.

7. **`addRelationship` reciprocal `hidden` value** (`sheets/EnhancedJournalSheet.js`, 2 sites incl. the compendium-emit path) — Ours (fix `59db6ea`): hardcoded `hidden: true`, fixing a bug where the previous code read the always-undefined `this.document.parent.hidden`. Theirs: `hidden: relationship.hidden` — a different but not provably-safe approach; a round-1 review finding caught a silently-auto-merged instance of theirs' version surviving into the emit-path hunk specifically, reintroducing the original exposure bug for compendium-crossing relationships. Kept ours throughout.

8. **DSA5 currency id-vs-name resolution** (`sheets/EnhancedJournalSheet.js`, 5 hunks; `helpers.js`) — Ours (fix `f2a445d`, follow-up to #795): a local `ident(c)` closure resolving dsa5 currencies by name instead of placeholder id. Theirs: an exported `currencyId()` helper with identical logic. Functionally identical independent fix; kept ours (the existing helper), removed theirs' now-unused `currencyId` export and a redundant guard loop that depended on it (would have thrown `ReferenceError` if left).

9. **Tab-queueing architecture** (`apps/enhanced-journal.js`, 9 hunks covering field decl, `queueTabChange`/`_activateTab`/`_updateTab`/`removeTab`, `addTab` call sites) — Ours (fix `b150f54`, #742): a promise-chain queue serializing tab-change operations, fixing a race condition where rapid tab switching corrupted which tab ended up active/rendered. Theirs: a simpler timestamp-based debounce (`_activatingTab` + a 1-second guard) with no actual serialization of overlapping async operations. Kept ours as the more robust fix; theirs' orphaned duplicate `removeDuplicateTabs()` method (auto-merged elsewhere, coexisting with ours' `removeDuplicateTab()`) was also removed.

10. **Header-controls Maximize toggle vs. dispatcher rewrite** (`apps/enhanced-journal.js`) — Ours (base feature, our scoping fix `4ef1b6c`/`630fb1a`): filters window controls to `configureSheet`, appends a Maximize/Restore toggle. Theirs: drops the Maximize control entirely in favor of a `_handleContextClick(event, action)` dispatcher wired to subsheet-provided controls. Kept ours; theirs' colliding `_getFrameButtons()`/`static fullscreen()` redesign (an alternate maximize UI, silently displacing ours' `toggleMaximize`/`fullscreen` pair with no conflict marker) was removed as redundant.

11. **`addTab(entity, options)` call sites** (`apps/enhanced-journal.js`, `open()`, 2 hunks) — Ours: `this.addTab(entity, Object.assign({activate:true, refresh:true}, options))` (fire-and-forget, consistent with the queueing architecture). Theirs: `await this.addTab(entity)` with no options merge, dropping caller-supplied tab options. Part of the same #742 fix; kept ours.

12. **`renderSubSheet` await/guard in `_onRender`** (`apps/enhanced-journal.js`) — Ours: awaits `renderSubSheet` under `_onRender`'s semaphore so `render()` doesn't resolve until subsheet content is committed (part of the #742 fix). Theirs: calls it unguarded/unawaited earlier in the method. Kept ours.
